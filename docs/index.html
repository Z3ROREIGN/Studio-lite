GUIA OFICIAL • STUDIO LITE

Aprenda a usar o Studio Lite.

Este é o manual completo do editor web. Aqui você encontra o passo a passo para criar projetos, usar o Explorer, trabalhar com scripts, configurar a integração com Roblox Open Cloud e entender o que cada área faz.

📱 Mobile🖥️ Desktop🌑 Tema escuro☁️ Roblox Open Cloud

Primeiros passos

O Studio Lite roda no navegador. Você não precisa instalar o Roblox Studio para utilizar as ferramentas do editor web.

Abra o Studio Lite.
Entre na página principal e aguarde o editor carregar.
Crie ou abra um projeto.
Use Novo para começar do zero ou as opções de arquivo disponíveis para trabalhar com um projeto existente.
Configure o projeto.
Defina o nome, Universe ID e Place ID quando for utilizar os recursos conectados ao Roblox.
Trabalhe pelo Explorer.
Selecione objetos, abra pastas, escolha scripts e confira as propriedades no painel lateral.
Salve antes de publicar.
Use Salvar para preservar o estado do projeto e só depois publique quando estiver tudo pronto.

Configuração

Para recursos locais do editor, basta abrir a aplicação. Para editar scripts de um jogo Roblox através do Studio RBXL, é necessário configurar uma API Key do Roblox com as permissões adequadas.

Universe IDID da experiência/universe que você quer acessar.
Place IDID do place dentro da experiência que contém os scripts.
API KeyChave do Roblox Open Cloud usada para autenticar as operações permitidas.
PermissõesA chave precisa ter acesso ao sistema de APIs de instâncias do universo/place e escopos de leitura e escrita necessários.
Importante: nunca publique sua API Key em GitHub, prints, chats ou código público. Use uma chave própria para cada usuário/ambiente quando o sistema for multiusuário.

Explorer

O Explorer representa a estrutura hierárquica do projeto. Pastas e containers podem ser expandidos; scripts podem ser selecionados para edição.

  • Pesquisar: digite o nome de um item no campo de filtro.
  • Abrir pasta: toque/clique no item que possui filhos.
  • Scripts: Script, LocalScript e ModuleScript podem abrir o editor de código quando suportados pelo modo atual.
  • Filhos de scripts: scripts que possuem filhos também podem ser expandidos e carregados.
  • Objetos não editáveis: no Studio RBXL, itens que não são scripts são usados principalmente para navegação/contexto; não confunda isso com criação de instâncias.
O carregamento do Explorer conectado ao Roblox é progressivo. Isso evita carregar toda a árvore de uma vez e reduz o número de chamadas à API.

Propriedades

Ao selecionar um objeto no editor, o painel de propriedades mostra os dados disponíveis para aquele contexto. No editor local, propriedades podem ser usadas para configurar o projeto/objeto. No Studio RBXL, a integração atual é focada principalmente em leitura da estrutura e edição de scripts.

Viewport 3D

Trabalhando com Scripts

O editor diferencia os três tipos principais de script do Roblox:

ScriptExecuta código no servidor.
LocalScriptExecuta código no cliente em contextos suportados pelo Roblox.
ModuleScriptFornece módulos reutilizáveis através de require().

Fluxo recomendado

Abra o Explorer e localize o script.
Selecione o Script, LocalScript ou ModuleScript.
Edite o Source no editor de código.
Salve as alterações.
Publique quando quiser enviar a alteração ao Roblox.
Atenção: a API de instâncias do Roblox possui restrições. Um script que estiver aberto no Roblox Studio, por exemplo, pode não aceitar uma atualização via Open Cloud.

Studio RBXL

O Studio RBXL é o modo de integração com um Place Roblox através do Roblox Open Cloud. Ele permite carregar a estrutura disponível pela API e trabalhar principalmente com scripts existentes.

O que ele faz: carrega a árvore disponível, permite navegar por containers, encontrar scripts, abrir Script/LocalScript/ModuleScript e enviar alterações de Source quando as permissões e condições da API permitem.
O que ele não significa: este modo não deve ser tratado como um importador universal de arquivo binário .rbxl. A API de Instances e um arquivo .rbxl completo são coisas diferentes.

Configurar o Roblox Open Cloud

Crie uma API Key no Roblox Creator Hub.
Escolha o acesso de API necessário para trabalhar com Instances.
Defina os recursos.
Selecione o universo/place que a chave poderá acessar.
Conceda leitura e escrita.
O Studio RBXL precisa conseguir ler a estrutura e atualizar scripts.
Informe a chave no local de configuração do Studio Lite.
Não coloque a chave diretamente no GitHub.
Informe Universe ID e Place ID.
Confira os números antes de carregar o Explorer.
Universe ID: 1234567890 Place ID: 9876543210 API Key: sua-chave-secreta Nunca coloque a API Key em: - README público - JavaScript público - GitHub - screenshots - mensagens enviadas para outras pessoas

Criar e editar scripts no Studio RBXL

Ao criar um script, o Studio RBXL abre uma etapa específica para escolher onde o script ficará antes de pedir o tipo e o nome.

Clique em + Script.
Abra a aba de criação de script.
Escolha o local.
Selecione Workspace, um serviço, uma pasta ou outro container que já esteja carregado no Explorer. O local selecionado aparece com o caminho completo.
Escolha o tipo.
Selecione Script, LocalScript ou ModuleScript.
Dê um nome ao script.
Informe o nome que aparecerá no Explorer.
Escolha como criar.
Criar local mantém um rascunho no editor; Criar no Roblox envia a criação para o Place conectado.

Local do script

O Studio prefere automaticamente o item atualmente selecionado no Explorer quando ele é um container válido. Se uma pasta ainda não foi carregada, abra-a primeiro para que ela apareça na lista de locais disponíveis.

Editar um script existente

Abra Studio RBXL.
Carregue o Place e espere o Explorer aparecer.
Expanda Workspace ou outro container.
Abra o Script, LocalScript ou ModuleScript desejado.
Edite o Source.
Use Salvar para aplicar a alteração pela API.
Se quiser atualizar vários scripts, faça as alterações e publique de forma controlada.
O carregamento de filhos é lazy: ao abrir um container, os filhos são buscados quando necessários. Isso também se aplica a scripts que possuem filhos.

Excluir arquivos e pastas

O Studio RBXL possui uma aba própria para exclusão, evitando apagar um item errado diretamente no Explorer.

Clique em Excluir.
Abra a aba/modal de exclusão na barra de ferramentas.
Procure o item.
Use o campo de pesquisa para localizar arquivos, pastas ou objetos já carregados.
Selecione o item.
A lista mostra nome, tipo e caminho completo para facilitar a conferência.
Confirme a exclusão.
O Studio diferencia rascunhos locais de objetos reais do Roblox antes de executar a operação.
Aguarde a atualização.
Ao excluir um objeto remoto, o Studio executa a operação permitida pelo Open Cloud e atualiza o Explorer.
Importante: a lista de exclusão trabalha com itens que já foram carregados no Explorer. Para encontrar itens mais profundos, abra primeiro o container correspondente.

Configuração necessária no Roblox Studio

Para a edição remota funcionar de forma confiável, há uma diferença importante entre o que precisa ficar no Roblox Studio e o que é feito pelo Studio Lite/Open Cloud. O Studio Lite não precisa de um script “ponte” para editar Script, LocalScript e ModuleScript: a API Engine Open Cloud atualiza diretamente essas instâncias. A Roblox informa que essas APIs permitem ler/atualizar esses três tipos de script, mas há restrições de sessão e de scripts abertos no Studio.

Recomendação: deixe o Roblox Studio aberto apenas quando precisar testar. Para editar/publicar pelo Studio Lite, não deixe o script que será atualizado aberto no editor de código do Roblox Studio.

O que você deve deixar no Roblox Studio

LocalScriptSimÉ suportado pelo Open Cloud Engine Instances.
ModuleScriptSimÉ suportado pelo Open Cloud Engine Instances.
Containers/serviçosSimWorkspace, ReplicatedStorage, ServerScriptService etc. continuam normalmente no projeto.

Permissões da API Key

Engine Instances: universe.place.instance:read universe.place.instance:write Publicação via Luau: universe.place.luau-execution-session:read universe.place.luau-execution-session:write

A experiência precisa ter uma sessão colaborativa habilitada para usar as APIs de Engine Instances. Para a publicação atual do Studio Lite, o fluxo Luau executa a alteração no servidor e usa SavePlaceAsync.

Salvar/Publicar o Place

SavePlaceAsync salva o estado do Place e, por padrão, publica a versão. A Roblox informa que ele só funciona em places criados com CreatePlaceAsync ou quando a API foi habilitada nas configurações do Place.

Se editar funcionar mas publicar falhar: confira a API de salvamento do Place nas configurações, os escopos de Luau Execution e os logs da tarefa Luau.

Criar no Roblox x Publicar alterações

Essas duas ações são diferentes e devem ser usadas em situações diferentes.

AçãoQuando usarResultado
Criar no RobloxQuando você criou um novo Script, LocalScript ou ModuleScript no editor.Cria uma nova instância no Roblox, usando o local escolhido no Explorer.
Publicar alteraçõesQuando você editou o Source de scripts que já existem no Roblox.Atualiza os scripts existentes que possuem alterações pendentes.
Regra simples: novo script → Criar no Roblox. Script existente editado → Publicar alterações.

Salvar, executar e publicar

SalvarUse para gravar o estado/alterações disponíveis no editor atual.
ExecutarInicia o modo de execução/preview oferecido pelo editor web.
PublicarEnvia as alterações para o destino suportado pelo modo atual.
ExportarUse quando precisar guardar uma representação/exportação que o editor disponibilizar.
Boa prática: teste primeiro, salve depois e publique por último. Em integrações com Open Cloud, erros de permissão, sessão ou limite da API podem impedir a atualização.

Guia completo: o que deixar no Roblox Studio

Esta seção reúne as informações práticas para usar o Studio Lite conectado a uma experiência Roblox. A regra principal é: não é necessário instalar um script-ponte no jogo para editar o Source de scripts. O Studio Lite usa Roblox Open Cloud.

Tipos de instância

TipoStatusUso
Script✅ SuportadoLeitura e atualização do Source.
LocalScript✅ SuportadoLeitura e atualização do Source.
ModuleScript✅ SuportadoLeitura e atualização do Source.
Workspace✅ ContainerUsado para navegar pela hierarquia.
ReplicatedStorage✅ ContainerUsado para localizar objetos/scripts.
ServerScriptService✅ ContainerLocal comum para Scripts de servidor.
ServerStorage✅ ContainerLocal comum para scripts/objetos do servidor.
StarterGui / StarterPlayer / StarterPack✅ ContainerPodem conter scripts e objetos do projeto.
Package⚠️ RestriçãoScripts pertencentes a Packages não devem ser usados como alvo de edição Open Cloud.

Enquanto o Roblox Studio estiver aberto

  • Você pode deixar o Roblox Studio aberto para testar o jogo.
  • Feche a aba do editor do script que o Studio Lite vai atualizar.
  • Se a API informar que existe uma sessão de edição ao vivo, feche o Script Editor e tente novamente.
  • Não mantenha o mesmo Source sendo editado simultaneamente nos dois editores.

O que NÃO precisa ser criado no jogo

❌ RemoteEvent especialNão é necessário para editar Source via Open Cloud.
❌ RemoteFunction especialNão é necessário para a conexão do Studio Lite.
❌ Script LoaderO Studio Lite não depende de um loader dentro do jogo.
❌ Plugin obrigatórioO fluxo Open Cloud não depende de plugin instalado no Roblox Studio.

Configuração da API Key

Para edição: universe.place.instance:read universe.place.instance:write Para publicação via Luau: universe.place.luau-execution-session:read universe.place.luau-execution-session:write

A experiência também precisa estar configurada para os recursos de Engine Instances quando esse fluxo for utilizado. A chave deve ser criada no Roblox Creator Hub e ter somente as permissões necessárias.

Como o Studio Lite funciona

1. Conexão.
O usuário informa API Key, Universe ID e Place ID.
2. Explorer.
O Studio Lite consulta a hierarquia do Place e identifica os objetos.
3. Edição.
Ao abrir um Script, LocalScript ou ModuleScript, o Source é obtido pela API.
4. Salvamento.
Alterações de Source usam a API de Engine Instances.
5. Publicação.
O fluxo de publicação usa Luau Execution no servidor e AssetService:SavePlaceAsync().

Requisitos para publicar

  • API Key com os escopos de Luau Execution.
  • Place configurado para permitir o salvamento usado pelo fluxo.
  • O alvo deve ser um Place válido da Universe.
  • A tarefa Luau precisa conseguir iniciar e concluir.
  • Se a edição funcionar e a publicação não, o problema normalmente está na configuração de salvamento/permissões, não no Source do script.
Importante: editar um Script e publicar o Place são operações diferentes. É possível a edição do Source funcionar enquanto a publicação falha por falta de permissão/configuração do Place.

Checklist antes de testar

☐ Universe ID correto ☐ Place ID correto ☐ API Key correta ☐ instance:read habilitado ☐ instance:write habilitado ☐ luau-execution-session:read habilitado ☐ luau-execution-session:write habilitado ☐ Sessão colaborativa configurada quando exigida ☐ Script não está aberto no editor do Roblox Studio ☐ Script não pertence a Package ☐ Place permite o salvamento/publicação ☐ Testar primeiro um Script simples

Segurança

  • Trate API Keys como senhas.
  • Use somente o menor conjunto de permissões necessário.
  • Não compartilhe sua chave com amigos, bots ou serviços desconhecidos.
  • Revogue e gere outra chave se suspeitar que ela vazou.
  • Em um produto multiusuário, cada usuário deve fornecer/autenticar seus próprios recursos; não use uma única chave secreta para todos.

Problemas comuns

ProblemaO que verificar
Studio RBXL não abreAtualize a página, limpe cache antigo, confira Universe ID, Place ID e configuração da chave.
403 ForbiddenA API Key não possui recurso/escopo suficiente ou o acesso não está autorizado.
429 Rate LimitedA API recebeu muitas solicitações. Aguarde e tente novamente; o backend possui tratamento de retry para esse caso.
409 ConflictUma operação do Roblox ainda está ocupada. Aguarde e tente salvar novamente.
500 Internal Server ErrorConfira o status da implantação e os dados enviados. Um 500 também pode indicar erro no backend.
Script não salvaVerifique se ele está aberto no Roblox Studio, se pertence a um pacote e se a chave tem escrita.
Busca não encontra itemO Explorer usa carregamento progressivo; expanda os containers necessários para que seus filhos sejam carregados.

Quando nada resolver

Recarregue a página, teste novamente com os mesmos IDs, confira a API Key e veja se o erro continua. Se continuar, anote a mensagem exata do erro — ela é muito mais útil do que apenas dizer que “não funciona”.

Colaboração em tempo real

Abra 🧩 Studio Platform → Colaboração, escolha um nome e conecte-se ao código da sala. O Studio usa Supabase Realtime para Broadcast das alterações e Presence para mostrar quem está online.

Segurança: o navegador usa somente uma chave publishable do Supabase. Nunca coloque uma chave secret/service_role no HTML ou JavaScript.
  1. Crie ou copie o código da sala.
  2. Envie o mesmo código para os colaboradores.
  3. Clique em Conectar sala em cada navegador.
  4. Use Sincronizar agora quando quiser enviar o estado atual imediatamente.

O modo colaborativo sincroniza o estado do editor web. Ele não transforma o Studio RBXL em um editor binário universal de arquivos .rbxl.
